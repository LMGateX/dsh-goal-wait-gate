# Opt-in startup owner — support contract and verification status

## Status

TypeScript implementation for issue [#10](https://github.com/LMGateX/dsh-goal-wait-gate/issues/10), separate from the unchanged legacy root entry. This is a development branch, **not an installed or release-ready plugin**. No profile configuration, live session, GUI or shared server was changed or restarted. A package-manager isolation incident temporarily changed SDK dependency links; the correction and verification limits are recorded below. A new development lock graph was generated by that unintended dependency synchronization, but a clean frozen-lock installation remains unverified. Do not use a version override to conceal this condition.

## Boot API, not a Loader row

The exported **goalWaitStartup** at dsh-goal-wait-gate/startup must be mounted directly on a fresh, unscoped Cordis root, after its shared service providers are ready and before any agents/delegations exist. Its immediate parent Fiber must be the root. No boot launcher adapter or Plugins page is shipped. An ordinary Loader/profile/bundle row has an EntryTree/Include parent and is rejected; simply awaiting it in an early prepare hook before dependencies exist also is not a complete bootstrap.

~~~ts
import { goalWaitStartup, getStartupState } from 'dsh-goal-wait-gate/startup'
// ctx is the actual Cordis root, NOT a profile-row / agent / nested plugin context.
// Mount and await the supported shared providers first; do not create agents yet.
const owner = await ctx.plugin(goalWaitStartup, {
  strategy: 'replacement', waitForJobs: true, waitForSubagents: true,
})
// Create agents only after successful startup. Restart the root to change strategy.
await owner.dispose()
const state = getStartupState(ctx)
await state?.cleanup // retained explicit managed cleanup result
~~~

The executable isolated bootstrap is [the synthetic native fixture](<../test/native-fixture.ts>), not a deployable launcher configuration. The default profile patch in the [README](<../README.md>) applies only to the legacy root export.

## Strategies and options

| Strategy | Scheduler | Background policy | Managed completion |
|---|---|---|---|
| activation (default) | pinned native-compatible TypeScript driver | owned disarm/resume bridge | managed-stop; closed or surfaced failed |
| replacement | pinned native-derived TypeScript driver | independent scheduling eligibility | managed-stop; closed or surfaced failed |
| native | actual original published native callback | none | unverified-native; closed-unverified or surfaced failed |
| off | none | none | root guard/tombstone retained |

The legacy root entry is still activation-only, does not own the official scheduler and still re-arms its owned holds on unload. Managed startup unload does NOT re-arm, even in activation mode. Native-compatible and original-native are intentionally different diagnostic labels.

Configuration is startup-only and rejects unknown keys, running-wait, unsupported strategies and inappropriate options. native/off accept no wait flags or maxHoldMs. replacement accepts waitForJobs/waitForSubagents but no maxHoldMs, even zero. activation retains the legacy optional timeout. These flags do not grant goal tool authority.

## Supported work observation

Normal replacement waiting keeps the parent genuinely idle, the durable goal active and activation armed; it introduces no long awaited Stop/pre-step waiter. It holds for:

1. Running/stopping Jobs with the **exact** parent owner id. Unowned or other-root Jobs do not hold.
2. Registered local subagent descendants whose **current runtime owner** is the exact live parent, including idle residents and nested descendants. Durable parentSession ancestry alone is insufficient; independently resumed/fork-like roots are not pulled under a former parent.
3. Observed local subagent/start epochs, indexed by unique runId and carrying the exact ancestor chain captured while registered. subagent/end releases only that runId; continuable end follows detach/disposal while one-shot end establishes only result settlement; an old settlement notice or old end cannot release a new residency with the same child session id.
4. A synchronous standard Jobs settlement-dispatch fence, cleared after bundled synchronous notice reporters. Quiet notices remain quiet; waking notices use ordinary native input. Neither grants automatic-round completion authority.

**One-shot distinction:** native one-shot end means result settlement, NOT final disposal. The supported standard tool-subagent path has a disposal-backed Job. While waitForSubagents=true, Jobs of kind subagent remain independently guarded and dispatch-fenced even with waitForJobs=false. Direct holder-owned ctx.subagents.start runs without that Job can outlive result/end and registry removal; their post-detach disposal/handoff is **unsupported**. A caller must not infer support from local=true alone.

Epoch records are created only on observed start. A pre-start abort creates no phantom debt; failed first acceptance closes its observed epoch without inventing an undelivered notice. Continuable end establishes the native notice **attempt**, not guaranteed transport delivery or model consumption; one-shot end establishes only result settlement, while its standard disposal-backed Job remains guarded until later settlement/dispatch. Registered descendants and Jobs remain independent guards because one-shot and continuable end have different semantics.

## Pinned hosts and invariants

Support is per published artifact identity, not a version range. The host profile is matched from the resolved driver bundle version **and** its SHA-256 together; an unpinned distribution is refused before any driver is mounted, and the ported behavior is selected only from that identity — never from configuration.

| Host distribution | Cordis | Goal-round-driver SHA-256 | Ported queued-round behavior |
|---|---|---|---|
| 0.2.0-rc.2 | 4.0.4 | 3bca01a2…db3b5ab450 | A cancelled or stale queued round retires through the activatable pause only; a kept queued message stays parked in the inbox. |
| 0.2.1-alpha.1 | 4.0.5-alpha.1 | 68ed0920…74317c69cf8 | An unclaimed queued round is also settled at idle by removing its inbox message, independent of the round pause. |

That single published difference is profile data, and the behavior-selection tests fail if either pin or its flag is changed. 0.2.1-alpha.1 no longer publishes the `./invariant` companion subpath, and an installation of that host may not ship `@deepseek-ai/dsh-invariants`; the companion is detected beside the resolved driver and is optional on both pins. The `native` strategy always mounts the actual published callback of the running host, so it inherits that host's own behavior without this port.

The full upstream MIT notice and both provenance records are distributed with lib/driver. No master-only queued-reservation behavior was silently adopted. The TypeScript port preserves native renderer/source/reservation, serial drive, checkpoints, admission-only roundsStarted counting, goal/ref/source authority, stale fences, cap, error and cancellation semantics. Tests distinguish ordinary notices from admitted goal rounds. Native user/parent cancellation may pause a goal; normal work waiting does not.

Policy checks run **after original housekeeping/checkpoint/attempt retirement/cap**, before reservation and on both sides of downstream pre-step. The cap still blocks the last admitted round even with newly started work. Max-token/error/checkpoint failure/external disarm/cancel retain their native exceptions to active/armed waiting.

## Ownership and topology limits

Preflight rejects an existing recognized owner without disposing it. A one-use exact callback+parent-Fiber ticket admits only the owned child; public registry fibers are counted rather than import callbacks. Known native/legacy/new-startup intrusion is vetoed synchronously before apply; own admission closes, holds cannot re-arm, and cleanup joins. Owner/child update is rejected; registry removal is not an async cleanup acknowledgement. A lifetime root tombstone prevents remount/hot handoff until a genuinely new root.

This is a **cooperating recognized-owner guard**, not arbitrary renamed/wrapped/hostile scheduler enforcement or a global/distributed lease. Core realm checking is a startup snapshot: a fixed shared topology and supported providers from the same module graph are prerequisites. Later isolated core realms, provider replacement, service changes, bootstrap after existing runs and separate active module copies are unsupported. There is no public outstanding-epoch bootstrap snapshot.

Version checking reads fresh locally resolvable package metadata from the plugin location and verifies the original source fingerprint. It does **not** attest the actual active provider graph. All core agent/loop/goal/session/projection/LLM/prompt/tools/goal-tools/jobs/jobs-local/jobs-tools/scope/driver artifacts must be resolvable at the pinned version, even if a given tool was not mounted; the invariants companion is required only when that installation publishes it beside the resolved driver. Existing subagents additionally require the bundled subagent/in-process/spawn/fork/tool/persistence/JSONL family; existing sessionQuery additionally requires query/query-sqlite. Custom/late providers are not authenticated by these checks.

## Admission, cleanup and release limitations

- Invisible prepublication/materialization requests and custom non-Jobs holders are not all represented by the public work observation.
- The last pre-step check precedes awaited request/config/prepareCall and final user-message commit. The passing public request-window counterexample deliberately admits one round while newly started work remains live. This is a decision-point guarantee, **not atomic zero admission at every instant**. Closing that window needs an authorized loop adaptation or upstream seam, not more claimed coverage of this driver.
- Managed-stop latches revocation before awaits, retains a shared promise and records surfaced synchronous stop/disarm/cancel errors and rejected explicit state/idle drain promises after draining all observed work. Native driver body failures already contained and logged stay contained. Arbitrary plugin effects and hidden failures swallowed inside Cordis are not universally observable.
- Original native has no public explicit stop handle; Cordis can log/swallow its disposer errors. Diagnostics always expose unverified-native and successful disposal return becomes closed-unverified, never verified closed. Both externally started child disposal and failed publication are joined, but that cannot recover swallowed errors.
- The cleanup Promise remains available through getStartupState after registry disappearance. Failure is retained; no strategy hot handoff follows disposal or failure.

## Verification layers and remaining delivery gate

The native fixture runs actual published SDK plugins and native invariants against deterministic local model adapters, public operations, synthetic ids and fresh temporary stores. Search is disabled and no host profile/session data is loaded. The legacy 25 tests use fake DSH services in real Cordis and must not be counted as replacement-native parity proof.

Public native assertions cover idle creation/stopping, quiet/wakeup ordering, genuine detach/disposal/end, failed acceptance, repeated cold-resumed epochs/stale notice/end, nested idle residency, independent durable lineage, one-shot disposal-backed Jobs with generic Jobs disabled, revision edit, exact completion authority, pre-step reservation fences, native cap/errors/checkpoint, user/parent queued/claimed/admitted cancellation, external pause/keepInbox/manual retention, downstream throw/reject, managed drain failure and the final request counterexample. Ownership tests separately cover actual mount/update/intrusion/lifetime/version/publication/disposal paths. This is not proof of all unknown providers, prepublication, mixed claimed multi-input permutations or final atomic admission.

The legacy host matrix typechecks **only the unchanged root entry, gate and legacy tests** on 0.1.7-alpha.2, 0.1.7-rc.2 and 0.2.0-rc.2. The native suite runs against a pinned host, and the same 86 assertions pass on both pins: on the installed 0.2.0-rc.2 and on a read-only 0.2.1-alpha.1 installation, with the sources and tests copied beside symlinked host packages and nothing installed or written into that installation. `node scripts/check-startup-host.ts <directory containing @deepseek-ai/*>` typechecks the shipped src/ against a host that already exists on the machine and reports whether its identity is pinned. Package export/build/attribution checks are separate from dependency clean-install reproducibility. The updated lock has registry integrity records and no private file/link resolutions; clean frozen-lock installation and native dependency-build policy are not accepted here. Do not release/install this development branch as a finished package. Direct build/test/package audits do not substitute for that release check.

### Operational isolation correction

An attempted pnpm 11 build unexpectedly performed dependency synchronization before the script. A test dependency group’s parent directory was a shared symlink; synchronization temporarily rewrote 25 SDK leaf links. Those links were restored to the verified original distribution, and the original native source fingerprint remains unchanged. The main linked plugin working tree and profile configuration remained unchanged; no GUI/server/session restart was performed. Temporary link replacement must not be represented as proof that no other running session could have been affected.

The implementation now owns its dependency-group directory; leaf links do not permit parent traversal writes. Subsequent compilation/test/pack audits use direct Node/compiler or npm ignore-scripts commands, not pnpm implicit dependency synchronization. No native build approval or plugin deployment was performed. Future clean-install validation must use an independent dependency directory without shared parent symlinks.
